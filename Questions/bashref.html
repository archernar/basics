1. Introduction

Bash (Bourne Again SHell) is a Unix shell and command language interpreter. A Bash script is a plain text file containing a series of commands.

Shebang

The first line of a script, the "shebang," tells the system which interpreter to use.

#!/bin/bash
# or for portability
#!/usr/bin/env bash

Executing a Script

1. Make the script executable:

chmod +x your_script.sh

2. Run it:

./your_script.sh

Alternatively, you can run it without making it executable:

bash your_script.sh

2. Best Practices (Script Header)

Start your scripts with these settings (the "unofficial strict mode") to catch common errors.

#!/usr/bin/env bash

# Exit immediately if a command exits with a non-zero status.
set -e

# Treat unset variables as an error when substituting.
set -u

# Exit status of the last command that threw a non-zero exit code is returned.
set -o pipefail

# Optional: Print each command to stderr before executing.
# set -x
Note: set -euo pipefail is a powerful combination. -e (or errexit) can have surprising behavior in if statements or while loops, but it's generally safer to have it on.

3. Basics

Comments

Comments start with a #. They are ignored by the interpreter.

# This is a full-line comment

echo "Hello"  # This is an inline comment

Command Substitution

Capture the output of a command into a variable. The modern $() syntax is preferred over backticks (``) because it nests easily.

# Preferred
current_date=$(date +%Y-%m-%d)
echo "Today is $current_date"

# Old style (avoid)
files=`ls -1`

Arithmetic

Use the $((...)) syntax for arithmetic expansion.

x=5
y=10
sum=$((x + y))
echo "Sum is: $sum"  # Output: Sum is: 15

# It also supports increment/decrement
((x++))
echo "x is now: $x" # Output: x is now: 6

4. Variables

Declaration & Assignment

No spaces around the = sign.

# Correct
name="Alice"

# Incorrect (will try to run "name" with args "=" and "Alice")
name = "Alice"

Usage

Reference a variable using the $ prefix, e.g., $name or ${name}. The curly braces are required when the variable name is adjacent to other characters.

fruit="apple"
echo "I have one $fruit"        # Works
echo "I have two ${fruit}s"     # Correct: I have two apples
echo "I have two $fruits"       # Incorrect: Tries to find variable $fruits

Variable Scopes

  • Global: Default scope. Accessible throughout the script.
  • Local: Use the local keyword inside functions to create a variable visible only within that function and its children.
global_var="I'm global"

my_func() {
    local local_var="I'm local"
    echo "$local_var"
    echo "$global_var" # Can access global
}

my_func
echo "$global_var"
echo "$local_var" # This will be empty (or error if 'set -u' is on)

5. Quoting

Quoting is critical in Bash to prevent word splitting and glob expansion.

Rule of thumb: Always double-quote your variables (e.g., "$my_var").

Double Quotes: "..."

Prevents word splitting and globbing, but allows variable ($var), command ($()), and arithmetic ($(())) substitution.

username="Alice"
echo "Hello, $username"  # Output: Hello, Alice

greeting="Hello    World"
echo "$greeting"       # Output: Hello    World
echo $greeting         # Output: Hello World (word splitting!)

Single Quotes: '...'

Prevents all substitutions. The string is treated literally.

username="Alice"
echo 'Hello, $username'  # Output: Hello, $username

6. Shell Expansions

Brace Expansion {...}

Generates arbitrary strings. Not for variables.

# Creates file_a.txt, file_b.txt, file_c.txt
touch file_{a,b,c}.txt

# Creates 001, 002, ... 100
echo {001..100}

Tilde Expansion ~

Expands to the home directory.

echo ~        # /home/username
echo ~/docs   # /home/username/docs

Parameter Expansion

Manipulate variables. Very powerful for setting defaults, substrings, etc.

Syntax Description Example (if var="foo.txt")
${var:-default} Use default if var is unset or null. file=${filename:-"default.txt"}
${var:=default} Use default if var is unset/null, and assign default to var. ${count:=0}
${var:?message} If var is unset/null, print message to stderr and exit. : ${HOSTNAME:?"HOSTNAME not set"}
${#var} Length of the string. ${#var} → 7
${var#pattern} Remove shortest match of pattern from start. ${var#*.} → txt
${var##pattern} Remove longest match of pattern from start. ${var##*.} → txt
${var%pattern} Remove shortest match of pattern from end. ${var%.*} → foo
${var%%pattern} Remove longest match of pattern from end. ${var%%.*} → foo
${var/find/replace} Replace first match of find with replace. ${var/txt/log} → foo.log
${var//find/replace} Replace all matches of find with replace. ${var//o/a} → faa.txt

7. I/O & Redirection

Commands have three standard streams: stdin (0), stdout (1), and stderr (2).

Syntax Description
> file Redirect stdout to file (overwrite).
>> file Redirect stdout to file (append).
< file Redirect file to stdin.
2> file Redirect stderr to file.
&> file Redirect both stdout and stderr to file. (Shorthand for > file 2>&1).
| Pipe: Redirect stdout of one command to stdin of another.
<<< "string" Here String: Pass "string" as stdin.
<< EOF Here Document: Read input until EOF is seen on its own line. 
# Pipe
ls -l | grep ".txt"

# Redirect stdout to file (overwrite)
echo "Hello" > output.log

# Redirect stderr to file (append)
grep "error" /var/log/syslog 2>> error.log

# Redirect stdout to /dev/null (silence output)
command_that_is_noisy > /dev/null

# Redirect both stdout and stderr to /dev/null
command_with_errors &> /dev/null

# Here Document
cat << EOF
This is line 1.
This is line 2.
The variable $USER is expanded.
EOF

# Here Document (disabling expansion)
cat << 'EOF'
The variable $USER is NOT expanded.
EOF

# Here String
grep "a" <<< "banana"

8. Operators & Tests

Conditional logic in Bash uses the test command, which has two forms: [ ... ] (classic) and [[ ... ]] (modern Bash-specific).

Best Practice: Always use the double-bracket [[ ... ]] form. It's more robust, supports pattern matching, and doesn't perform word splitting on variables.

String Comparisons (inside [[ ... ]])

Operator Description
"$str1" == "$str2" True if strings are equal. (Note: = is a valid synonym for == here).
"$str1" != "$str2" True if strings are not equal.
"$str1" < "$str2" True if str1 sorts before str2 (lexicographically).
"$str1" > "$str2" True if str1 sorts after str2.
-z "$str" True if string is empty (zero length).
-n "$str" True if string is not empty.
"$str" =~ regex True if string matches the extended regular expression.

Integer Comparisons (inside [[ ... ]] or (( ... )))

Use these operators inside [[ ... ]]:

Operator Description
$int1 -eq $int2 Equal
$int1 -ne $int2 Not Equal
$int1 -gt $int2 Greater Than
$int1 -ge $int2 Greater Than or Equal
$int1 -lt $int2 Less Than
$int1 -le $int2 Less Than or Equal

Alternatively, use the more C-like arithmetic context (( ... )):

x=5
y=10

if (( x < y )); then
    echo "$x is less than $y"
fi

File Tests (inside [[ ... ]])

Operator Description
-e "$file" True if file exists (any type).
-f "$file" True if file is a regular file.
-d "$dir" True if dir is a directory.
-s "$file" True if file is not empty (size > 0).
-r "$file" True if file is readable.
-w "$file" True if file is writable.
-x "$file" True if file is executable.

Logical Operators (inside [[ ... ]])

Operator Description
! expression Logical NOT
expr1 && expr2 Logical AND
expr1 || expr2 Logical OR

9. Control Flow

if / then / elif / else / fi

The [ ... ] or [[ ... ]] is actually a *command* (test). The if statement checks the exit code of that command (0 for success/true, non-zero for failure/false).

read -p "Enter a number: " num

if [[ "$num" -gt 100 ]]; then
    echo "That's a big number!"
elif [[ "$num" -eq 42 ]]; then
    echo "That's the answer."
else
    echo "That's a small number."
fi

You can test any command, not just [[ ... ]]:

# Check if grep finds a match
if grep -q "root" /etc/passwd; then
    echo "User 'root' exists."
fi

case / esac

Useful for matching a variable against several patterns.

read -p "Enter 'start', 'stop', or 'status': " command

case "$command" in
    start)
        echo "Starting service..."
        # ...
        ;;
    stop|end)  # Multiple patterns
        echo "Stopping service..."
        # ...
        ;;
    status)
        echo "Checking status..."
        # ...
        ;;
    *) # Default (wildcard)
        echo "Unknown command: $command"
        exit 1
        ;;
esac

10. Loops

for Loop

# Looping over a list of items
fruits="apple banana cherry"
for fruit in $fruits; do
    echo "I like $fruit"
done

# Looping over a range (Bash 3+)
for i in {1..5}; do
    echo "Number: $i"
done

# Looping over files
for file in /var/log/*.log; do
    echo "Processing $file"
done

# C-style for loop
for (( i=0; i<5; i++ )); do
    echo "C-style count: $i"
done

while Loop

Executes as long as the condition is true (exit code 0).

count=0
while [[ $count -lt 5 ]]; do
    echo "Count is $count"
    ((count++))
done

A common pattern: reading a file line by line.

while IFS= read -r line; do
    echo "Read line: $line"
done < "input.txt"
Note: IFS= prevents trimming leading/trailing whitespace. -r prevents backslashes from being interpreted. This is the safest way to read lines.

until Loop

Executes as long as the condition is false (non-zero exit code).

count=0
until [[ $count -eq 5 ]]; do
    echo "Until count is $count"
    ((count++))
done

Loop Control

  • break: Exits the current loop entirely.
  • continue: Skips the rest of the current iteration and starts the next one.
for i in {1..10}; do
    if (( i == 3 )); then
        continue  # Skip 3
    fi
    if (( i == 8 )); then
        break     # Stop at 8
    fi
    echo $i
done
# Output: 1 2 4 5 6 7

11. Functions

Declaration

# Style 1 (preferred)
my_func() {
    echo "Hello from the function!"
}

# Style 2 (Bash only)
function my_func_alt {
    echo "Hello again!"
}

Calling

Just use the function name like a command.

my_func

Parameters (Positional)

Functions access arguments using the same special variables as scripts:

  • $1: First argument
  • $2: Second argument, etc.
  • $#: Number of arguments
  • $@: All arguments as a list of separate, quoted strings (e.g., "$@")
  • $*: All arguments as a single string (e.g., "$*")
Best Practice: Use "$@" to forward all arguments to another command. 
greet() {
    local name="$1"
    local greeting="$2"
    echo "$greeting, $name!"
}

greet "Alice" "Good morning" # Output: Good morning, Alice!

Return Values

Functions "return" in two ways:

1. Exit Status: An integer (0-255) using the return keyword. 0 means success, non-zero means failure. This is checked via $?.

is_file() {
    if [[ -f "$1" ]]; then
        return 0 # Success
    else
        return 1 # Failure
    fi
}

if is_file "/etc/hosts"; then
    echo "It's a file!"
fi

2. Standard Output: To "return" data (like a string), echo it from the function and capture it with command substitution $().

get_date() {
    date +%Y-%m-%d
}

today=$(get_date)
echo "Today is $today"

12. Arrays

Indexed Arrays

# Declare
my_array=("apple" "banana" "cherry")

# Access element (0-indexed)
echo ${my_array[0]} # Output: apple

# Access all elements
echo ${my_array[@]} # Output: apple banana cherry

# Get length
echo ${#my_array[@]} # Output: 3

# Add element
my_array+=("orange")

# Loop over array
for item in "${my_array[@]}"; do
    echo "Item: $item"
done

Associative Arrays (Bash 4+)

Key-value maps. Must be declared with declare -A.

# Declare
declare -A user
user["name"]="Alice"
user["id"]=101
user["role"]="admin"

# Access element
echo ${user["name"]} # Output: Alice

# Get all keys
echo ${!user[@]} # Output: name id role (order not guaranteed)

# Get all values
echo ${user[@]} # Output: Alice 101 admin

# Loop over keys
for key in "${!user[@]}"; do
    echo "Key: $key, Value: ${user[$key]}"
done

13. Script Arguments

These are the same special variables used in functions.

# Script: ./my_script.sh foo bar baz

echo "Script name: $0"   # ./my_script.sh
echo "First arg: $1"     # foo
echo "Second arg: $2"    # bar
echo "Arg count: $#"     # 3
echo "All args (list): $@" # foo bar baz
echo "All args (string): $*" # foo bar baz

getopts

The built-in way to parse simple POSIX-style options (e.g., -f, -v, -o file).

#!/bin/bash
# Usage: ./script.sh -v -f /path/to/file

verbose=0
output_file=""

# 'vf:o:' defines the options:
# v: A simple flag (no argument)
# f: A simple flag (no argument)
# o: An option that requires an argument (the colon ':')

while getopts "vfo:" opt; do
  case $opt in
    v)
      verbose=1
      ;;
    f)
      echo "Flag -f was triggered."
      ;;
    o)
      output_file="$OPTARG"
      ;;
    \?) # Handle invalid options
      echo "Invalid option: -$OPTARG" >&2
      exit 1
      ;;
    :) # Handle missing option arguments
      echo "Option -$OPTARG requires an argument." >&2
      exit 1
      ;;
  esac
done

# Shift arguments so $1 refers to non-option arguments
shift $((OPTIND-1))

echo "Verbose: $verbose"
echo "Output file: $output_file"
echo "Remaining arguments: $@"

14. Special Variables

Variable Description
$? Exit status of the last executed command (0 for success, non-zero for failure).
$$ Process ID (PID) of the current script.
$! PID of the last background command (run with &).
$0 Name of the script.
$# Number of positional parameters (arguments).
$@ All positional parameters as individual quoted strings. (Use "$@").
$* All positional parameters as a single string. (Use "$*"). 
ls /nonexistent-file > /dev/null 2>&1
echo "Exit status of ls: $?"  # Will be non-zero

echo "This script's PID is $$"

sleep 10 &
echo "PID of background sleep: $!"

15. Debugging & Traps

Using set

You can set these options at the top of your script (see Best Practices) or on the command line.

  • set -x (or xtrace): Print each command to stderr before it is executed. Extremely useful for debugging.
  • set -v (or verbose): Print shell input lines as they are read.
# Run your script in debug mode
bash -x ./your_script.sh

# Or, enable it mid-script
echo "Debugging starts here"
set -x
my_var="test"
echo "$my_var"
set +x # Disable debug mode
echo "Debugging ends here"

trap

The trap command allows you to execute a command when your script receives a signal.

# Define a function to run on exit
cleanup() {
    echo "Cleaning up temporary files..."
    rm -f /tmp/my_script_*.tmp
}

# Set the trap: call 'cleanup' on EXIT (normal or abnormal)
trap cleanup EXIT

# Also trap interrupt (Ctrl+C) and terminate signals
trap cleanup INT TERM

echo "Creating temp file..."
touch /tmp/my_script_123.tmp

echo "Sleeping for 10 seconds... (press Ctrl+C to test)"
sleep 10

echo "Script finishing."
# 'cleanup' will run here automatically
